Organigrama General y División de Fases del Proyecto

Estructuración modular de las 5 fases de ingeniería y su correspondencia con la rúbrica oficial (100% / 40 Pts).
Fase 1
Base de Datos Centralizada
Ponderación: 10 %
13 tablas relacionadas en MariaDB (InnoDB, UTF-8), claves PK/FK, roles `admin`/`usuario`, restricciones CHECK y datos de prueba.
Fase 2
Desarrollo API REST
Ponderación: 20 %
Servicios HTTP en PHP (GET, POST, PUT, DELETE) para 3 módulos: Horarios, Solicitudes y Aulas/OTP, con validación y códigos HTTP.
Fase 3
Plataforma Web
Ponderación: 20 %
Interfaz adaptable en HTML5/Bootstrap/JS, Dashboard administrativo, portal de docentes, formularios validados y filtros.
Fase 4
App Móvil Flutter
Ponderación: 20 %
Aplicación móvil en Dart/Flutter, autenticación, consumo de la misma API REST, réplica de los 3 módulos y navegación nativa.
Fase 5
Integración & Sincronización
Ponderación: 15 %
Sincronización bidireccional Web ↔ API ↔ BD ↔ Móvil, pruebas de consistencia y compilación de APK Android funcional.
Fase 6
Seguridad, Doc & Demo
Ponderación: 15 %
Seguridad y hash (5%), Documentación técnica institucional (5%) y Demostración práctica ante el Dr. Aurelio Mex Mex (5%).

Sesión #01 • Fase 2.1 (Recuperación) Sesión Recuperada
API REST: Estandarización de Endpoints y CRUD de Horarios
FechaMartes 10/Nov/2026
Horario11:50 – 12:40 h
UbicaciónLab IOT (F-107)
FaseAPI REST (Módulo 1)

1. Objetivos Técnicos y Pedagógicos

  • Definir la arquitectura de servicios web REST en PHP bajo el servidor local Apache de XAMPP.
  • Implementar capa de validación de entrada con tipos estrictos (enteros, fechas ISO, horas 24h y enums) en api/helpers.php.
  • Desarrollar el CRUD del **Módulo 1: Carga Académica y Horarios** (api/carga_academica.php) con detección de conflictos por solapamiento de aulas.

2. Actividades Desarrolladas y Entregables

  • Programación de endpoints GET, POST, PUT y DELETE consumiendo la base de datos MariaDB aulas_inteligentes.
  • Algoritmo SQL de prevención de colisiones horarias: validación estricta de cruce de días, horas y rangos de fechas lectivas.
  • Respuestas estándar en formato JSON con cabeceras HTTP adecuadas (200 OK, 201 Created, 400 Bad Request, 409 Conflict, 422 Unprocessable).

3. Observaciones y Cumplimiento

  • Se verificó el funcionamiento local en XAMPP. La sesión se da por acreditada y lista para el enlace del frontend y los módulos subsiguientes.

Sesión #02 • Fase 2.2 Sesión de Hoy (12/Nov)
API REST: Solicitudes de Aulas, Cerraduras IoT y Enlace Web
FechaJueves 12/Nov/2026
Horario09:00 – 10:40 h
UbicaciónLab 9 (C-114)
FaseAPI REST (Módulos 2 y 3)

1. Justificación de Calendario & Objetivos

  • Nota de calendario: El Miércoles 11 de noviembre hubo suspensión oficial de actividades escolares; se retoma de forma continua hoy 12 de noviembre.
  • Desarrollar el flujo del **Módulo 2: Solicitudes de Aulas** (api/solicitudes.php y api/solicitud_responder.php) para cambios de aula o peticiones extraordinarias.
  • Implementar el **Módulo 3: Aulas, Cerraduras y OTP** (api/aulas.php, api/otp_solicitar.php y api/cerradura_abrir.php) con bitácora de accesos.
  • Enlazar y verificar el consumo directo de la API REST desde el frontend Web servido por Apache en XAMPP.

2. Actividades Desarrolladas y Entregables

  • Creación de endpoints para registro de solicitudes por parte de docentes y aprobación/rechazo por administradores con comentarios de auditoría.
  • Mecanismo de generación de código temporal OTP de 6 dígitos con expiración automática (5 minutos) y registro de evento en la tabla accesos.
  • Configuración de la pila de servicios en XAMPP con Apache activo en puerto local y MariaDB conectado en puerto 3306.

3. Observaciones y Cumplimiento

  • Se consolidaron 2 de los 3 módulos administrativos exigidos por la rúbrica. Los servicios quedan listos para su integración y pruebas en la siguiente sesión de frontend y Postman.
