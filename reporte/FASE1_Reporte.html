ACTIVIDAD 1.1Diseño Entidad-Relación

El modelo está normalizado y organizado en cuatro dominios: seguridad y usuarios, infraestructura física, operación académica y control IoT. Todas las relaciones usan claves foráneas explícitas con reglas de integridad referencial.

Lectura del diagrama: las llaves indican la cardinalidad. Un usuario puede tener muchas sesiones, accesos, OTP y solicitudes; un edificio concentra muchas aulas; cada aula puede tener varios nodos IoT; y cada nodo genera telemetría y alertas.

Extracto: roles y tabla de usuarios

-- Roles iniciales del sistema (rúbrica FASE 1: Admin y Usuario)
INSERT INTO roles (nombre, descripcion) VALUES
  ('admin',         'Administrador: acceso total al dashboard IoT, gestión de usuarios...'),
  ('usuario',       'Usuario estándar (docente/estudiante): consulta su horario...'),
  ('mantenimiento', 'Rol técnico opcional: visualiza nodos IoT...');

CREATE TABLE usuarios (
  id_usuario    INT UNSIGNED NOT NULL AUTO_INCREMENT,
  google_sub    VARCHAR(64)  NULL,
  email         VARCHAR(150) NOT NULL,
  nombre        VARCHAR(120) NOT NULL,
  matricula     VARCHAR(20)  NULL,
  id_rol        INT UNSIGNED NOT NULL DEFAULT 2,   -- 2 = usuario
  foto_url      VARCHAR(400) NULL,
  activo        TINYINT(1)   NOT NULL DEFAULT 1,
  creado_en     TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id_usuario),
  UNIQUE KEY uq_usuarios_email      (email),
  UNIQUE KEY uq_usuarios_google_sub (google_sub),
  UNIQUE KEY uq_usuarios_matricula  (matricula),
  CONSTRAINT fk_usuarios_rol FOREIGN KEY (id_rol) REFERENCES roles(id_rol),
  CONSTRAINT chk_usuarios_email CHECK (email LIKE '%_@_%.__%'),
  CONSTRAINT chk_usuarios_nombre CHECK (nombre NOT REGEXP '[0-9]'),
  CONSTRAINT chk_usuarios_activo CHECK (activo IN (0,1))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
Nota de seguridad: el acceso se realiza con Google Identity Services, por lo que la tabla no almacena contraseñas locales. El rol se asigna desde roles.id_rol y todo usuario nuevo entra como usuario.

Guion sugerido para la demostración (5–7 min)

  1. Mostrar el diagrama ER y explicar los cuatro dominios del modelo.
  2. Abrir phpMyAdmin y listar las 13 tablas de aulas_inteligentes.
